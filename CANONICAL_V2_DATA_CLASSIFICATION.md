# Canonical V2 Data Classification

## Classification rules

- `ORACLE_DERIVED`: source evidence that can be rebuilt from read-only Oracle.
- `ERP_MASTER_CONFIG`: intentional ERP-owned configuration that must be exported/imported.
- `ERP_DERIVED`: reproducible state generated from source evidence and master/config rules.
- `HISTORICAL_DISCARDABLE`: operational history that may be omitted only after explicit acceptance.
- `REVIEW_REQUIRED`: provenance or retention requirement must be resolved before baseline/import.

## Domain classification

| Domain / representative relations | Classification | Provenance and V2 treatment |
| --- | --- | --- |
| `source_orders`, `source_workbank_items`, `source_stock_items`, `source_audit_events` | ORACLE_DERIVED | Rebuild through read-only Oracle bootstrap. Preserve source IDs, timestamps, hashes and sync provenance. |
| Oracle release order/header/line snapshots | ORACLE_DERIVED | Re-query Oracle; must support partial release and source quantity evidence. |
| `sync_batches`, heartbeat/runs/refresh requests | ERP_DERIVED | Start clean; generated by V2 sync. Do not import old run history. |
| Current source views and reconciliation views | ERP_DERIVED | Recreate from canonical baseline; never import view data. |
| Organizations and membership mapping | ERP_MASTER_CONFIG | Export/import deliberately; Auth user linkage requires a separate identity plan. |
| Supabase Auth users/sessions | REVIEW_REQUIRED | Not ordinary table copy. Define invitation/account migration without exposing credentials. |
| Product families/types/products | ERP_MASTER_CONFIG | Preserve approved canonical identity and natural keys. Do not recreate duplicates from Oracle descriptions. |
| Product source mappings/aliases | ERP_MASTER_CONFIG | Preserve source system + source product natural keys and confidence/provenance. |
| Operations, work centres, production resources | ERP_MASTER_CONFIG | Preserve canonical codes and active state. |
| Routings, revisions, routing operations, product-routing assignments | ERP_MASTER_CONFIG | Preserve revision identity and immutable released definitions. |
| Source task/operational-code mappings | ERP_MASTER_CONFIG | Preserve deterministic mappings and confidence classification. |
| Shift templates/rules | ERP_MASTER_CONFIG | Required by event, labour and capacity calculations. |
| Production areas, capacity profiles/rules, staffing layouts | ERP_MASTER_CONFIG | Preserve only approved current configuration; document effective dates and natural keys. |
| KPI definitions, targets and rate rules | ERP_MASTER_CONFIG | Preserve business definitions/rates; calculated results are not master data. |
| Planning configuration and legacy overrides | ERP_MASTER_CONFIG / REVIEW_REQUIRED | Separate reusable config from historical plans and temporary overrides. |
| Release lifecycle state/history | ERP_DERIVED with audit-retention review | Rebuild active state from Oracle evidence. Decide separately whether historical audits must be retained. |
| Production Demand and demand mappings | ERP_DERIVED | Recalculate from Oracle lines, mappings, release evidence and routing. Do not import totals to force parity. |
| Manufacturing Orders, MO lines/operations | ERP_DERIVED with execution-history review | Rebuild only safe active state. In-progress/completed historical execution requires explicit cutover treatment. |
| Release Queue | ERP_DERIVED | Canonical view/function output; no row import. |
| Machine Load and Product Mix projections | ERP_DERIVED | Recalculate. NOT_APPROVED stays informational and separate from active load. |
| `production_events` derived from Oracle audit | ORACLE_DERIVED / ERP_DERIVED | Recreate deterministically from source events; manual Screen Print events require separate handling. |
| Manual Screen Print events/jobs | ERP_MASTER_CONFIG or operational carry-forward review | Not Oracle-derived. Active jobs may require migration; historical events require retention decision. |
| Deputy raw timesheets/import batches | REVIEW_REQUIRED | External/SharePoint-derived; define source replay availability and retention. |
| Labour segments | ERP_DERIVED | Recalculate from accepted Deputy rows and canonical segmentation rules. |
| KPI results/trends/dashboard views | ERP_DERIVED | Recalculate after source and labour bootstrap. |
| Production plans/items/history | REVIEW_REQUIRED | Active plans may require controlled carry-forward; old plan history may be discardable. |
| Maintenance asset categories/prefixes/component prefixes | ERP_MASTER_CONFIG | Preserve naming/config rules. |
| Maintenance assets/installations | ERP_MASTER_CONFIG | ERP-owned physical master data; preserve IDs/codes where integrations or QR labels depend on them. |
| Preventive plans/tasks | ERP_MASTER_CONFIG | Preserve schedules, task definitions and asset relationships. |
| Maintenance parts/inventory locations | ERP_MASTER_CONFIG | Preserve natural keys and opening stock strategy. |
| Maintenance work orders, comments, labour, downtime, checklists, audit | REVIEW_REQUIRED | Operational/legal history, not Oracle-derived. Explicit retention decision required; do not discard by default. |
| Maintenance inventory transactions | REVIEW_REQUIRED | Preserve if needed for audit; otherwise import validated opening balances with provenance. |
| Maintenance attachments and `maintenance-private` objects | REVIEW_REQUIRED | Requires secure storage migration and referential validation. |
| Old sync logs, transient failed imports and obsolete diagnostic snapshots | HISTORICAL_DISCARDABLE candidate | Discard only after explicit approval and confirmation they are not audit evidence. |
| Legacy calculated KPI/cache tables | HISTORICAL_DISCARDABLE candidate | Rebuild from canonical sources unless retention is explicitly required. |

## Required master/config export manifest

Before any import, create one row per dataset with:

| Field | Requirement |
| --- | --- |
| Source | Exact current DEV/production relation and read-only extraction query |
| Destination | Canonical V2 table |
| Row count | Source, exported and imported counts |
| Natural key | Stable uniqueness rule |
| Duplicate rule | Reject, merge or deterministic update |
| Dependencies | Parent records/order of import |
| Validation | Constraints, referential checks and business invariants |
| Provenance | Export timestamp, source project and checksum |

## Decisions required before `001_canonical_baseline.sql`

1. Auth user/account migration method.
2. Active versus historical Production Demand/MO carry-forward boundary.
3. Manual Screen Print active-job migration.
4. Deputy raw data replay/retention.
5. Active production-plan carry-forward.
6. Maintenance operational history and attachments retention.
7. Inventory opening balance versus transaction-history migration.
8. Explicit list of accepted historical discard domains.

No dataset will be copied merely because it exists in a legacy database.
